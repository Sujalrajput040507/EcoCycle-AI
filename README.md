# EcoCycle AI — Antigravity Starter Pack

**Tagline:** Turn Waste Into Value  
**Purpose:** A planning and project-context pack for the GRAVITON 2026 hackathon.

## What this folder is

This pack explains the product idea, boundaries, proposed architecture, team workflow, event timeline, and acceptance criteria. It is deliberately **documentation only**. It contains no EcoCycle HTML, CSS, JavaScript, backend source code, or prebuilt submission implementation.

GRAVITON's published rules, as shared with the team, allow research, planning, and design before the event, while submission code must be written during the 24-hour hackathon. Keep this pack as planning material and begin all actual submission-code creation only when the organisers officially start hacking.

## Files

- `AGENTS.md` — persistent instructions for Antigravity. Keep this at the project/workspace root.
- `brain.md` — product vision, problem, users, value proposition, and MVP definition.
- `planning.md` — priorities, deliverables, roles, dependencies, and risk plan.
- `implementation.md` — proposed system structure, screens, data concepts, API boundaries, and matching logic.
- `methodology.md` — team engineering process, collaboration, AI-agent usage, and integration rules.
- `timeline.md` — 24-hour execution plan and conservative internal freeze.
- `testing.md` — acceptance criteria and manual test checklist.
- `demo_and_pitch.md` — truthful demo sequence and judge-question preparation.
- `decisions_and_assumptions.md` — decisions, assumptions, scope exclusions, and fallback choices.
- `docs/` — a place for additional design notes, diagrams, and event-confirmed details.

## How to use this in Antigravity

1. Create an empty folder for the project/workspace. If the event requires the repository to be created at hacking start, do not create the submission repository or code before then. You may keep this documentation pack separately until the start, then copy the planning files into the permitted workspace if event rules allow it.
2. Put `AGENTS.md` at the root of the Antigravity workspace. Keep the other Markdown files beside it.
3. Open the folder in Antigravity and ask the agent to read `AGENTS.md`, `brain.md`, `planning.md`, `implementation.md`, `methodology.md`, and `timeline.md`.
4. Before hacking starts, ask only for summaries, clarification of the plan, design review, task breakdown, and risk identification. Do not ask the agent to create EcoCycle submission source code before the official start.
5. At the official start, confirm the organisers' exact rules and deadline. Then tell Antigravity that coding is authorised and ask it to implement one small, reviewable task at a time.
6. Review every proposed change, run the app, test it, and make sure a team member can explain it before accepting it.

## First message to Antigravity

Use this as your opening instruction after loading the files:

> Read `AGENTS.md` and all project planning documents. Do not write, generate, scaffold, or modify any EcoCycle application source code yet. First give us a concise understanding of the problem, target users, MVP, proposed architecture, team responsibilities, 24-hour timeline, risks, and acceptance criteria. Identify contradictions or missing decisions. Ask no more than the single most important question, and do not invent facts. We will explicitly tell you when the official hacking period begins and coding is authorised.
